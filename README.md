# Workout Diary

Консольный дневник тренировок на Java — учебный pet-проект.

Цель — пройти путь от консольного приложения на чистой Java
до REST API на Spring Boot + PostgreSQL, покрытого тестами
и упакованного в Docker.

## Что умеет сейчас

- Ввод тренировки с клавиатуры: название, упражнения, подходы
  (вес, повторения, сложность, комментарий)
- Проверка каждого поля при вводе, с повтором запроса при ошибке
- Статистика тренировки: тоннаж, максимальный вес, средняя сложность
- Сохранение тренировок в текстовый файл `workouts.txt`
- Загрузка истории при запуске; если файл повреждён,
  программа сообщает номер испорченной строки и не падает

## Структура

```
workout-diary/
├── pom.xml                                   — описание проекта для Maven
└── src/
    ├── main/java/io/github/pikachy357/workoutdiary/
    │   ├── Main.java                         — точка входа, консольный ввод
    │   ├── model/                            — предметная область
    │   │   ├── Workout.java
    │   │   ├── Exercise.java
    │   │   ├── ExerciseSet.java
    │   │   └── Describable.java
    │   └── storage/                          — сохранение и загрузка
    │       └── WorkoutStorage.java
    └── test/java/io/github/pikachy357/workoutdiary/
        ├── model/                            — тесты модели
        └── storage/                          — тесты хранилища
```

| Пакет | Класс | Назначение |
|---|---|---|
| `workoutdiary` | `Main` | консольный ввод и запуск программы |
| `workoutdiary.model` | `Workout` | тренировка: дата, название, список упражнений |
| `workoutdiary.model` | `Exercise` | упражнение: название, описание, список подходов |
| `workoutdiary.model` | `ExerciseSet` | подход: вес, повторения, сложность, комментарий |
| `workoutdiary.model` | `Describable` | интерфейс краткого описания объекта |
| `workoutdiary.storage` | `WorkoutStorage` | сохранение и загрузка тренировок из файла |

Сущности связаны композицией: тренировка содержит упражнения,
упражнение содержит подходы. Тесты лежат в тех же пакетах,
что и проверяемые классы.

## Формат файла

Каждая строка начинается с метки уровня, поля разделены `;`:

```
WORKOUT;2026-09-29;День ног
EXERCISE;Приседания;Приседания со штангой
SET;80.0;10;5;разминка
SET;100.0;8;7;рабочий
```

Символ `;` запрещён во вводимом тексте, чтобы не ломать формат.

## Запуск

Нужны JDK 25+ и Maven (в IntelliJ IDEA Maven уже встроен).

```
mvn compile
java -cp target/classes io.github.pikachy357.workoutdiary.Main
```

Или открыть проект в IntelliJ IDEA и запустить `Main.main()`.
Файл `workouts.txt` создаётся в папке, из которой запущена программа.

В консоли Windows перед запуском нужно выполнить `chcp 65001`,
иначе кириллица при вводе распознаётся неправильно.

## Тесты

```
mvn test
```

Тесты на JUnit 5 проверяют:

- расчёт статистики упражнения (тоннаж, максимальный вес);
- валидацию подходов (отрицательный вес, сложность вне диапазона);
- защиту списков подходов и упражнений от изменения извне;
- сохранение тренировки в файл и загрузку обратно
  (во временную папку через `@TempDir`).

## Что использовано

- ООП: классы, инкапсуляция, композиция, интерфейсы
- Пакеты и модификаторы доступа
- Неизменяемые подходы, защитные копии списков
  (`new ArrayList<>(...)`, `List.copyOf(...)`)
- Коллекции: `List`, `ArrayList`
- Лямбды, `Predicate`, Stream API
- Исключения: валидация в конструкторах, проверяемые и непроверяемые
  исключения, обёртка с сохранением причины
- `Scanner` для консольного ввода
- `java.nio.file` (`Files`, `Path`) для работы с файлами
- `LocalDate` для дат
- Maven для сборки
- JUnit 5 для тестов

## Известные ограничения

- Название упражнения вводится вручную каждый раз, поэтому
  «Жим» и «жим лёжа» считаются разными упражнениями.
  Планируется справочник упражнений.
- Консольный ввод (`Main`) тестами не покрыт, проверяется вручную.
- В консоли Windows для ввода кириллицы нужна команда `chcp 65001`.

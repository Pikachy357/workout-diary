# Workout Diary

Workout Diary — консольный дневник силовых тренировок на Java. В нём можно записать тренировку по подходам, посмотреть общий тоннаж и узнать, какой максимальный вес удалось поднять в каждом упражнении за всю историю.

Это учебный backend-проект. Он начинался с модели тренировки и консольного ввода, затем появились файловое хранилище, статистика и тесты. Сейчас проект умеет сохранять тренировку в PostgreSQL через JDBC. Ближайший этап — загрузить её обратно из трёх связанных таблиц. Дальнейшая цель — REST API на Spring Boot с PostgreSQL и запуском в Docker.

**Текущий стек:** Java 25, Maven, JUnit 5, PostgreSQL, JDBC.

## Что умеет дневник

- Принимает с клавиатуры название тренировки, упражнения и подходы. Дата тренировки подставляется автоматически.
- Для каждого подхода записывает вес, количество повторений, сложность по шкале от 1 до 10 и комментарий.
- Проверяет ввод. Например, при отрицательном весе или неверном количестве повторений программа предлагает ввести значение ещё раз.
- Выводит количество упражнений и общий тоннаж за тренировку. Для отдельного упражнения показывает тоннаж и максимальный вес. Модель также умеет вычислять среднюю сложность подходов.
- Загружает историю из `workouts.txt` и находит личный рекорд по каждому упражнению.
- Сохраняет тренировку вместе со всеми упражнениями и подходами в PostgreSQL в одной транзакции.

В проекте две точки входа с общим консольным вводом:

| Точка входа | Что происходит при запуске |
|---|---|
| `Main` | Загружает историю из файла и выводит личные рекорды. Затем принимает новую тренировку, показывает её статистику и дописывает в `workouts.txt`. |
| `JdbcDemo` | Принимает тренировку и сохраняет её в PostgreSQL. Выводит строки из трёх таблиц, список тренировок по датам и рекорды, рассчитанные SQL-запросом. |

## Пример тренировки и расчёта

Допустим, в тренировке «День ног» записаны два подхода приседаний:

| Подход | Вес | Повторения | Сложность | Комментарий |
|---|---:|---:|---:|---|
| 1 | 80 кг | 10 | 5 | Разминка |
| 2 | 100 кг | 8 | 7 | Рабочий подход |

Тоннаж упражнения равен `80 × 10 + 100 × 8 = 1 600 кг`. Максимальный вес — `100 кг`, средняя сложность — `6`. Если на следующей тренировке выполнить приседания со `105 кг`, рекорд по упражнению «Приседания» обновится до `105 кг`.

### Назначение классов

| Класс | За что отвечает |
|---|---|
| `Main` | Консольный ввод с проверками, работа с файловой историей и вывод статистики. |
| `JdbcDemo` | Сценарий запуска с PostgreSQL. Использует тот же ввод тренировки, что и `Main`. |
| `Workout` | Хранит дату, название и упражнения. Рассчитывает общий тоннаж тренировки. |
| `Exercise` | Хранит название, описание и подходы. Рассчитывает тоннаж, максимальный вес и среднюю сложность упражнения. |
| `ExerciseSet` | Описывает один подход. Вес, повторения, сложность и комментарий задаются при создании. |
| `Describable` | Задаёт общий метод `describe()` для краткого описания тренировки, упражнения или подхода. |
| `StatisticsService` | Обходит всю историю и находит максимальный вес по каждому названию упражнения. Возвращает рекорды в порядке названий. |
| `WorkoutStorage` | Дописывает тренировки в текстовый файл и восстанавливает из него список объектов `Workout`. |
| `JdbcWorkoutStorage` | Сохраняет тренировку и связанные с ней записи в PostgreSQL. Управляет транзакцией. |

Модель построена на композиции: `Workout` содержит список `Exercise`, а каждый `Exercise` — список `ExerciseSet`. Добавление проходит через `addExercise()` и `addSet()`. Конструкторы копируют переданные списки, а геттеры возвращают `List.copyOf(...)`. Так вызывающий код может читать состав тренировки, а изменения проходят через методы модели.

## Файловое хранилище

При запуске `Main` читает `workouts.txt` из рабочей папки приложения. Если файла ещё нет, дневник начинает с пустой истории. При первом сохранении файл создаётся, а следующие тренировки дописываются в конец.

Каждая строка начинается с метки. `WORKOUT` открывает тренировку, `EXERCISE` добавляет в неё упражнение, а `SET` относится к последнему прочитанному упражнению.

```text
WORKOUT;2026-11-09;День ног
EXERCISE;Приседания;Со штангой
SET;80.0;10;5;разминка
SET;100.0;8;7;рабочий подход
```

Поля разделены точкой с запятой, поэтому консольный ввод проверяет текст на символ `;`. При ошибке разбора, например если `SET` встретился до первого упражнения, загрузчик сообщает номер строки. `Main` выводит сообщение и позволяет продолжить ввод новой тренировки.

## PostgreSQL и JDBC

### Схема базы данных

| Таблица | Что хранится | Как связана с другими таблицами |
|---|---|---|
| `workouts` | Идентификатор, дата и название тренировки | Одна тренировка может содержать несколько упражнений. |
| `exercises` | Идентификатор, название и описание упражнения | `workout_id` ссылается на `workouts.id`. |
| `exercise_sets` | Идентификатор, вес, повторения, сложность и комментарий | `exercise_id` ссылается на `exercises.id`. |

Внешние ключи поддерживают связь между записями. При удалении тренировки PostgreSQL каскадно удаляет её упражнения и подходы. Для подходов в схеме заданы ограничения: вес от нуля, положительное количество повторений и сложность от 1 до 10.

Схема находится в [schema.sql](src/main/resources/schema.sql). В [data.sql](src/main/resources/data.sql) есть примеры для проверки запросов: три тренировки, четыре записи об упражнениях и шесть подходов.

### Как сохраняется целая тренировка

Один вызов `JdbcWorkoutStorage.save(workout)` использует одно соединение и одну транзакцию:

1. `save()` открывает `Connection` и отключает автоматическую фиксацию через `setAutoCommit(false)`.
2. Вставка в `workouts` возвращает созданный идентификатор через `RETURNING id`.
3. Для каждого упражнения этот идентификатор записывается в `exercises.workout_id`. Вставка упражнения возвращает свой `id`.
4. Подходы записываются в `exercise_sets` с идентификатором соответствующего упражнения.
5. После успешной записи всех данных `commit()` фиксирует тренировку. При `SQLException` метод вызывает `rollback()` и передаёт ошибку вызывающему коду.

Например, в базе комментарий к подходу ограничен 255 символами. Если комментарий ко второму подходу длиннее, откатываются также первый подход, упражнение и сама тренировка. Для дневника это важно: при следующем чтении пользователь увидит только целиком сохранённые тренировки.

### Как читаются данные

`JdbcDemo` выполняет запросы через `PreparedStatement` и читает результаты с помощью `ResultSet`. Один запрос выводит тренировки по дате. Другой соединяет `exercises` с `exercise_sets`, группирует строки по названию упражнения и находит максимальный вес через `MAX(weight)`.

Следующий этап для `JdbcWorkoutStorage` — метод `loadAll()`, который будет собирать из строк базы список `Workout` с вложенными упражнениями и подходами.

## Запуск

Для сборки нужны **JDK 25 и Maven**. Команды выполняются из корня репозитория. В IntelliJ IDEA проект можно открыть по `pom.xml` и выбрать JDK 25 как Project SDK.

### Файловый дневник

```bash
mvn compile
java -cp target/classes io.github.pikachy357.workoutdiary.Main
```

В IntelliJ IDEA достаточно запустить `Main.main()`. После сохранения программа выведет абсолютный путь к `workouts.txt`.

Если в консоли Windows некорректно вводится кириллица, перед запуском можно переключить кодовую страницу командой `chcp 65001`.

### Демонстрация с PostgreSQL

`JdbcDemo` подключается к `jdbc:postgresql://localhost:5432/workout_diary` под пользователем `postgres`. Пароль берётся из переменной окружения `DB_PASSWORD`.

1. Запусти PostgreSQL. Для первого запуска создай базу и примени схему:

   ```bash
   psql -h localhost -U postgres -d postgres -c "CREATE DATABASE workout_diary"
   psql -h localhost -U postgres -d workout_diary -f src/main/resources/schema.sql
   ```

2. Если нужны примеры для просмотра истории и рекордов, загрузи их сразу после создания таблиц. Скрипт использует фиксированные идентификаторы и рассчитан на свежую схему:

   ```bash
   psql -h localhost -U postgres -d workout_diary -f src/main/resources/data.sql
   ```

3. В конфигурации запуска `JdbcDemo` в IntelliJ IDEA открой **Environment variables** и задай `DB_PASSWORD` со значением пароля пользователя `postgres`.
4. Запусти `JdbcDemo.main()` и введи тренировку. После записи в консоли появятся данные из таблиц и результаты запросов.

## Тесты

```bash
mvn test
```

В проекте 12 тестов на JUnit 5. Для их запуска достаточно JDK и Maven.

| Тестовый класс | Что проверяет |
|---|---|
| `ExerciseTest` | Расчёт тоннажа и максимального веса, отклонение отрицательного веса и сложности выше 10, защиту списка подходов. |
| `WorkoutTest` | Защиту списка упражнений от изменения через геттер и через список, переданный в конструктор. |
| `StatisticsServiceTest` | Поиск рекорда по нескольким тренировкам и результат для пустой истории. |
| `WorkoutStorageTest` | Пустую историю при отсутствии файла и восстановление сохранённой тренировки. Для файлов используется временная папка `@TempDir`. |

Транзакционное сохранение дополнительно проверено на PostgreSQL. При корректном вводе сохранились одна тренировка, одно упражнение и два подхода. При ошибке во втором подходе количество новых строк во всех трёх таблицах оказалось равным нулю.

## Известные ограничения

- Рекорды группируются по точному названию упражнения. «Жим» и «Жим лёжа» образуют две отдельные записи.
- `Main` работает с файлом, а `JdbcDemo` — с PostgreSQL. У каждого варианта своя история.
- JDBC-демонстрация выводит строки таблиц. Загрузка полной истории в объекты `Workout` пока реализована для файла.
- Консольный ввод проверяется вручную. Автоматические тесты в репозитории покрывают модель, сервис статистики и файловое хранилище.
